# StockPOS Frontend

เว็บแอป StockPOS สำหรับการจัดการร้าน รองรับการใช้งานบนมือถือ แท็บเล็ต และคอมพิวเตอร์ สร้างด้วย React, CRACO, Tailwind CSS, Axios และ Socket.IO Client

## หน้าจอและฟังก์ชัน

### การเข้าสู่ระบบและสิทธิ์

- หน้าเข้าสู่ระบบ สมัครสมาชิก และเข้าใช้งานแบบผู้เยี่ยมชม
- รองรับสิทธิ์ Admin, Staff และ User
- เก็บ session token ใน browser และตรวจสอบบัญชีกับ backend เมื่อเปิดระบบ
- User เห็นประวัติออเดอร์ของตนเอง ส่วนผู้เยี่ยมชมเปิด dashboard ตรวจสอบคิวได้โดยไม่ต้องล็อกอิน

### Admin

- ศูนย์ปฏิบัติการร้านแบบ 3D สำหรับแท็บเล็ตและคอมพิวเตอร์
  - หน้าร้านแสดงออเดอร์และคิว
  - สต็อกแสดงวัตถุดิบจริงจากระบบ พร้อมข้อมูลเมื่อ hover
  - ฝั่งผู้ดูแลแสดงภาพรวมการเงิน
  - แสดงคิวลูกค้าหรือ rider ตามช่องทางออเดอร์
- หน้าขายและออเดอร์: แสดง 5 ออเดอร์ล่าสุด พร้อมปุ่มไปยังหน้าออเดอร์ทั้งหมด เลือกเมนู ช่องทางขาย ชื่อลูกค้า/เบอร์โทร ตะกร้าสินค้า ส่วนลด คูปอง และแต้มสมาชิก
- หน้าออเดอร์ทั้งหมดค้นหาได้จากเลขออเดอร์ คิว ชื่อลูกค้า หรือเบอร์โทร และกรองตามวันที่ สถานะ และช่องทางขายได้ทั้ง Admin และ Staff
- กดเมนูทุกครั้งเพื่อเปิด popup เลือกตัวเลือกของแก้ว เช่น ระดับหวาน น้ำแข็ง ขนาดแก้ว และท็อปปิง ก่อนเพิ่มลงตะกร้า พร้อมแสดงส่วนเพิ่มราคาและแก้ไขตัวเลือกของแก้วเดิมได้
- ตะกร้าแสดงผ่านปุ่มไอคอน เพื่อเปิด popup ตรวจสอบรายการ ส่วนลด คูปอง แต้มสมาชิก การชำระเงิน และยืนยันออเดอร์จากจุดเดียว
- เลือกวิธีชำระเงิน รับเงินสดและคำนวณเงินทอน พร้อมเปิด/ปิดกะเงินสดของผู้ใช้งาน
- จอเตรียมสินค้าแยกคิว “กำลังทำ” และ “พร้อมรับ” พร้อมส่งมอบออเดอร์, พิมพ์ใบครัว และพิมพ์ใบเสร็จจากรายการออเดอร์
- จัดการวัตถุดิบ: เพิ่ม แก้ไข ลบ รับของเข้า ผู้ขาย ประวัติใบรับของ และ Export Excel
- จัดการเมนูและสูตรวัตถุดิบ (BOM) พร้อมสถานะพร้อมขาย/วัตถุดิบไม่พอ และปุ่มปิดขายชั่วคราว
- หน้าการเงิน: กรองวันที่และเลขออเดอร์ เพิ่ม/แก้ไข/ลบค่าใช้จ่าย เพิ่ม/แก้ไข/ลบรายการขาย ดูยอดขายแยกตามช่องทางและวิธีชำระเงิน ตรวจสอบประวัติปิดกะเงินสด ปิดยอดประจำวัน และ Export Excel
- รายงานเชิงธุรกิจ: เลือกวันนี้, 7 วัน, เดือนนี้ หรือกำหนดช่วงเอง เพื่อดูยอดขายรายเมนู, ช่องทาง, ชั่วโมงขายดี, GP, ส่วนลด, ต้นทุนล็อตจริง และกำไรหลัง GP/ส่วนลด
- เมนู **พร้อมเปิดใช้จริง**: ดาวน์โหลดข้อมูลสำรองธุรกิจ, ตรวจประวัติการแก้ไข, และทำ checklist ทดสอบสิทธิ์/การขายครบเส้นทางก่อนเปิดร้าน
- ปิดยอดประจำวัน: Admin ปิดยอดได้เมื่อปิดกะเงินสดของวันนั้นแล้ว ระบบเก็บ snapshot ยอดขาย/ค่าใช้จ่าย/กำไร และล็อกรายการขายกับค่าใช้จ่ายของวันนั้น
- เมนูจัดการคูปอง: สร้าง แก้ไข เปิด/ปิด กำหนดสิทธิ์และช่วงเวลาใช้งานของคูปองจากเมนูแยกสำหรับ Admin
- เมนูช่องทางขาย: Admin เพิ่ม แก้ไข และเปิด/ปิดช่องทางขาย พร้อมกำหนดค่าธรรมเนียมเป็นเปอร์เซ็นต์ ซึ่งระบบจะใช้คำนวณรายรับสุทธิของออเดอร์ใหม่
- ฟอร์มเพิ่มหรือแก้ไขข้อมูลสำหรับวัตถุดิบ เมนู ผู้ขาย/รับของเข้า ใบสั่งซื้อ รายการขาย ค่าใช้จ่าย และคูปอง เปิดผ่านปุ่มเป็น popup เพื่อให้หน้ารายการอ่านง่ายทั้งมือถือและคอมพิวเตอร์

### Staff

- หน้าขายแบบเน้นงานหน้าร้าน ใช้งานได้ดีบนมือถือและเดสก์ท็อป
- กดเลือกเมนูและเปิดตะกร้าผ่าน popup แบบเดียวกับหน้า Admin เพื่อให้ใช้งานเร็วบนหน้าจอขนาดเล็ก
- สร้างออเดอร์ ระบุชื่อลูกค้า/ชื่อเล่นและเบอร์โทรได้ตามต้องการ
- ใช้ส่วนลดจำนวนเงินหรือเปอร์เซ็นต์
- ตรวจสอบและใช้คูปองก่อนยืนยันออเดอร์
- ค้นหาแต้มสมาชิกจากเบอร์โทร ใช้แต้มเป็นส่วนลด และแสดงแต้มที่คาดว่าจะได้รับก่อนชำระ
- ดู 5 คิวงานล่าสุดและเปลี่ยนสถานะออเดอร์ พร้อมปุ่มไปยังหน้าออเดอร์ทั้งหมด

### User และผู้เยี่ยมชม

- User ดูแต้มสมาชิกคงเหลือ รวมถึงประวัติการสั่งซื้อและสถานะออเดอร์ที่สัมพันธ์กับบัญชีหรือเบอร์โทรของตน
- ผู้เยี่ยมชมดู dashboard คิวออเดอร์ของวันปัจจุบันได้ทันที และกรอกเบอร์โทรเพื่อค้นหา/กรองรายการของตนในวันนี้
- แสดงชื่อเล่น/ชื่อลูกค้า เลขคิว ช่องทาง และรายการสินค้า

## การทำงานของส่วนลดและคูปอง

หน้า POS แสดงยอดก่อนลด ส่วนลดหน้าร้าน ส่วนลดคูปอง และยอดสุทธิแยกกันชัดเจน

- ส่วนลดหน้าร้านเลือกเป็นบาทหรือเปอร์เซ็นต์ได้
- กรอกรหัสคูปองแล้วกด “ใช้คูปอง” เพื่อให้ backend ตรวจสอบ
- backend เป็นผู้คำนวณและบันทึกยอดจริง ป้องกันคูปองหมดอายุ ใช้เกินสิทธิ์ หรือยอดไม่ถึงขั้นต่ำ
- การเปลี่ยนตะกร้าหลังใช้คูปองควรตรวจสอบคูปองอีกครั้งก่อนยืนยันออเดอร์

## สมาชิกและแต้มสะสม

เมื่อกรอกเบอร์โทรในหน้า POS ระบบจะแสดงแต้มสมาชิกของเบอร์นั้นและให้พนักงานเลือกใช้แต้มได้สูงสุดตามยอดออเดอร์ (ทุก 25 บาทรับ 1 แต้ม, 10 แต้มลด 1 บาท, ใช้แต้มได้ไม่เกิน 50% ของยอดหลังส่วนลดหน้าร้านและคูปอง) หากยังไม่เคยมีประวัติ ระบบจะสร้างบัญชีสะสมแต้มให้เมื่อยืนยันออเดอร์

ลูกค้าที่ล็อกอินด้วยบัญชีซึ่งมีเบอร์โทร จะเห็นยอดแต้มคงเหลือในหน้าประวัติของตัวเอง พร้อมแต้มที่ได้รับและใช้ในแต่ละออเดอร์

## การตั้งค่าตัวเลือกเมนู

Admin ไปที่ **เมนูสินค้า** แล้วเพิ่ม “ตัวเลือกเมนู” ในเมนูที่ต้องการ กำหนดชื่อกลุ่ม จำนวนขั้นต่ำ/สูงสุด และแต่ละตัวเลือกพร้อมราคาเพิ่ม/ลดได้ เมนูที่มีตัวเลือกจะแสดงหน้าต่างให้พนักงานเลือกก่อนลงตะกร้า ส่วนเมนูปกติยังเพิ่มได้ทันที หากเลือกผิด ให้กด **ปรับความหวาน / ท็อปปิ้ง** ที่รายการนั้นในตะกร้า ระบบจะคงจำนวนแก้วเดิมและรวมกับรายการที่มีตัวเลือกเหมือนกันโดยอัตโนมัติ

## จอเตรียมสินค้าและใบเสร็จ

Admin เปิด **จอเตรียมสินค้า** จากแถบเมนู เพื่อเห็นบัตรคิวแบบอ่านง่ายบนแท็บเล็ตหรือจอครัว แต่ละคิวเดินตามสถานะ `COOKING → READY → COMPLETED` โดยจะแสดงเมนู ความหวาน/ท็อปปิ้ง ชื่อลูกค้า และช่องทางขาย ปุ่ม **พิมพ์ใบครัว** สร้างตั๋วสำหรับจุดเตรียมสินค้า ส่วนปุ่ม **ใบเสร็จ** ในรายการออเดอร์สร้างเอกสารที่มีรายการสินค้า ส่วนลด วิธีชำระ และเงินทอน

Admin ไปที่ **ตั้งค่าการพิมพ์** เพื่อกำหนดกระดาษใบเสร็จและใบครัวเป็น 58 หรือ 80 มม. บันทึกชื่อจุดพิมพ์เพื่ออ้างอิง และทดสอบพิมพ์ได้ การเลือกเครื่องพิมพ์จริงทำผ่านหน้าต่างพิมพ์ของระบบปฏิบัติการทุกครั้ง เนื่องจากเว็บเบราว์เซอร์ไม่อนุญาตให้เลือกเครื่องพิมพ์โดยอัตโนมัติ

## ความเสถียรและการแจ้งข้อผิดพลาด

- Frontend ตรวจสถานะ `GET /api/health` ทุก 30 วินาที และตรวจซ้ำทันทีเมื่อ browser กลับมาออนไลน์
- แถบแจ้งเตือนจะแสดงเมื่ออินเทอร์เน็ตหลุด, API ติดต่อไม่ได้, ฐานข้อมูลไม่พร้อม หรือ Socket.IO กำลังเชื่อมต่อใหม่
- เมื่อ real-time กลับมา ระบบจะรีเฟรชออเดอร์และข้อมูลหน้าร้านเพื่อซิงก์สถานะล่าสุด
- POS จะไม่ส่งออเดอร์ใหม่ขณะระบบยังไม่พร้อม เพื่อลดความเสี่ยงออเดอร์ซ้ำ หากการส่งขาดตอน ระบบจะแจ้งให้ตรวจรายการออเดอร์ก่อนยืนยันซ้ำ
- API mutation ที่ผิดพลาดแสดง popup กลางจอพร้อมรหัส เช่น `API_400`, `API_401`, `API_403`, `API_409`, `API_500`, `API_TIMEOUT` และ `API_NETWORK` รวมถึงข้อความจริงจาก backend

## การชำระเงินและกะเงินสด

หน้า POS รองรับเงินสด, QR พร้อมเพย์, โอนเงิน, บัตร และอื่น ๆ เมื่อเลือกเงินสด ผู้ใช้งานต้องเปิดกะก่อน แล้วกรอกยอดที่รับเพื่อให้ระบบแสดงเงินทอนทันที ปุ่มเปิด/ปิดกะอยู่ในส่วนการชำระเงินและหน้าร้าน เมื่อปิดกะให้กรอกยอดเงินที่นับได้ ระบบจะแสดงยอดคาดการณ์และยอดต่างให้ตรวจสอบ

## การรับวัตถุดิบเข้า

หน้า **วัตถุดิบ** มีฟอร์ม “รับวัตถุดิบเข้าคลัง” สำหรับเลือกผู้ขาย ระบุวันเวลารับของ เพิ่มวัตถุดิบได้หลายรายการต่อใบ และกรอกต้นทุนจริงต่อหน่วย ระบบคำนวณยอดรับรวมและปรับจำนวนคงเหลือกับต้นทุนเฉลี่ยของวัตถุดิบหลังบันทึกสำเร็จ ประวัติใบรับของล่าสุดจะแสดงใต้ฟอร์ม พร้อมทางลัดเพิ่มผู้ขายใหม่

แต่ละรายการรับเข้าระบุ **เลขล็อต** และ **วันหมดอายุ** ได้ กด **ดูล็อต** ที่วัตถุดิบเพื่อดูจำนวนคงเหลือ ต้นทุน ผู้ขาย และวันหมดอายุของแต่ละล็อต ระบบขายจะเลือกตัดล็อตที่หมดอายุเร็วที่สุดก่อนโดยอัตโนมัติ (FEFO) และจะไม่ใช้ล็อตที่หมดอายุแล้ว

หน้า POS ของ Admin และ Staff จะแสดงสถานะเมนูทุกแก้ว หากวัตถุดิบจากล็อตที่ยังไม่หมดอายุไม่พอตามสูตร BOM เมนูนั้นจะเป็น **วัตถุดิบไม่พอ** และกดเพิ่มลงตะกร้าไม่ได้ Admin เห็นจำนวนแก้วโดยประมาณที่ทำได้สูงสุดในหน้าเมนูสินค้า และเลือก **ปิดขาย** เพื่อหยุดขายชั่วคราวได้ โดยเปิดขายอีกครั้งแล้วระบบจะประเมินจากสต็อกปัจจุบันให้ทันที

เมื่อเมนูเหลือจำนวนที่ขายได้ตั้งแต่ 1–5 แก้ว หน้า POS และหน้าเมนูสินค้าจะแสดงแถบเตือนสีเหลืองพร้อมชื่อเมนูและจำนวนโดยประมาณ เกณฑ์นี้กำหนดจาก backend ผ่าน `MENU_LOW_STOCK_THRESHOLD` เพื่อให้ปรับตามรูปแบบร้านได้

Admin มีหน้า **ศูนย์แจ้งเตือน** ที่รวมเมนูใกล้หมด วัตถุดิบต่ำกว่าจุดแจ้งเตือน ล็อตใกล้หมดอายุภายใน 7 วัน และล็อตที่หมดอายุแล้วไว้ในรายการเดียว กรองได้เป็นทั้งหมด / เร่งด่วน / ต้องติดตาม และแต่ละรายการมีปุ่มพาไปยังหน้าจัดการที่เกี่ยวข้อง

ใต้ศูนย์แจ้งเตือนมี **รายการสั่งซื้อแนะนำ** สำหรับวัตถุดิบที่ต่ำกว่าจุดเตือน ระบบแนะนำจำนวนให้กลับไปมีอย่างน้อย 2 เท่าของจุดแจ้งเตือน ผู้ดูแลแก้จำนวน เลือกผู้ขาย และ Export Excel เพื่อส่งสั่งซื้อได้ ก่อนนำของมาบันทึกรับเข้าคลังตามปกติ

ผู้ดูแลสามารถกด **บันทึกใบสั่งซื้อ** จากรายการแนะนำได้ทันที ใบสั่งซื้อจะเริ่มเป็นฉบับร่าง แล้วเปลี่ยนเป็น “ส่งให้ผู้ขายแล้ว” หรือ “รับของแล้ว” ได้ ก่อนกดรับของ ผู้ดูแลตรวจและแก้จำนวนจริง ต้นทุนจริง เลขล็อต วันหมดอายุ และหมายเหตุได้ จากนั้นระบบจะสร้างใบรับของ เพิ่มล็อต ปรับยอดคลัง และอัปเดตสถานะใบสั่งซื้อในรายการเดียวกัน

ในรายการวัตถุดิบ กด **ตรวจนับ / ของเสีย** เพื่อบันทึกยอดที่นับได้จริง หรือหักวัตถุดิบที่เสีย/หมดอายุโดยต้องระบุเหตุผล ระบบแสดงสัญญาณตามล็อตที่หมดอายุแล้วและใกล้หมดอายุภายใน 7 วันโดยอัตโนมัติ

## การเชื่อมต่อ Backend

กำหนด URL ของ backend ด้วย environment variable:

```env
REACT_APP_API_URL=https://your-backend.example.com
```

หากไม่กำหนด ระบบจะใช้ URL production ที่ตั้งไว้ใน `src/App.jsx` โดยอัตโนมัติ

Frontend เรียก API เพื่อดึงออเดอร์ สินค้า สต็อก การเงิน และใช้ Socket.IO เพื่ออัปเดตสถานะออเดอร์แบบ real-time

## การติดตั้งและรัน

ติดตั้งแพ็กเกจ:

```bash
npm install
```

รันโหมดพัฒนา:

```bash
npm run dev
```

สร้าง production build:

```bash
npm run build
```

รัน production build ในเครื่อง:

```bash
npm start
```

`npm start` จะสร้าง build ก่อนอัตโนมัติหากยังไม่มี แล้วเปิด static server ตามค่า `PORT` (ค่าเริ่มต้น 3000)

## โครงสร้างสำคัญ

```text
src/App.jsx                         สถานะระบบ, session, API และ real-time sync
src/components/ui/GlassLayout.jsx   หน้าจอ Admin: POS, สต็อก, เมนู, การเงิน
src/components/ui/StaffWorkspace.jsx หน้าจอ Staff
src/components/ui/UserOrderStatus.jsx หน้าประวัติและสถานะออเดอร์ของ User
src/components/ui/AnonymousOrderStatus.jsx หน้า public dashboard ตรวจสอบออเดอร์
src/components/ui/OperationsRoom3D.jsx ศูนย์ปฏิบัติการร้านแบบ 3D
src/assets/                          ภาพประกอบและสินทรัพย์ของ UI
```

## เทคโนโลยี

- React 19 และ React DOM
- Tailwind CSS และ PostCSS ผ่าน CRACO
- Axios สำหรับ REST API
- Socket.IO Client สำหรับข้อมูล real-time
- Three.js และ React Three Fiber สำหรับศูนย์ปฏิบัติการ 3D
- SheetJS (`xlsx`) สำหรับ Export Excel

## หมายเหตุการแสดงผล

- ออกแบบให้ responsive โดยเน้น mobile และ desktop
- ฉาก 3D จะแสดงเฉพาะหน้าจอแท็บเล็ต/คอมพิวเตอร์ เพื่อไม่ให้มือถือใช้ทรัพยากรเกินจำเป็น
- มือถือจะแสดง fallback ที่อ่านง่ายและใช้งานส่วนจัดการร้านได้ครบ
